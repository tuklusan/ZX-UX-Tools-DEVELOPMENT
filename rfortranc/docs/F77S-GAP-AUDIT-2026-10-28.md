# F77S requirements gap audit — 2026-10-28

Scope: **ANSI X3.9-1978 Subset FORTRAN**, not full FORTRAN 77. Audit against the repository's `main` at `e03c72542a5048469110c100f502856b708f5f87`, with `rfortranc/rfortranc/translator.py` Git blob `6374bc07d4ff98e76596fe235801ef64dd9efc63`. This is source inspection, **not** a new executable conformance run.

Normative reference: [ANSI X3J3/90.4, Appendix D, pages D-1 through D-6](https://www.sternwarte.uni-erlangen.de/~ai05/vorlesungen/astrocomp/f77-standard.pdf), together with the subset-facing text of the standard. Existing working scope is recorded in `docs/F77S-MATRIX.md`. Appendix D is an **overview**, not a replacement for each section's full subset text.

**Interpretation of status**: **Missing** = source code rejects/does not lower a required form. **Partial** = representative cases work, other required cases do not. **Unproven** = implementation may exist but representative or broad conformance proof is missing. Prior 95 native / 65 host-vs-ZX-UX / 13 bounds / four-release successes are real but do not prove full-subset coverage.

## Current status corrections to existing documentation

- `F77S-MATRIX.md` row D3.9 says subprogram DATA is rejected; this is **outdated** relative to `translator.py:convert`, `data_init.py`, and `f77s_subdata.f`. Its final explanatory sections also describe fixed CHARACTER arrays/dummies as implemented, so the table must be reconciled before using it as a binary missing/present checklist.
- `README.md` retains some introductory text saying `array dummy arguments are not supported`, `REAL READ is missing`, or `CHARACTER arrays are missing`; these statements are superseded by later passages and tests in the **same file**. No audit should count those full-feature headings as entirely missing.
- The existing `--std f77s` **acceptance test is not a conformance test**. Code generation can accept source outside F77S rules, or reject perfectly valid F77S programs, while still passing the currently pinned fixtures.
- **Standard exclusions, not backlog:** DOUBLE PRECISION/COMPLEX, PRINT, list-directed READ/WRITE, PARAMETER, BLOCK DATA, ENTRY/alternate return, CLOSE, INQUIRE, .EQV./.NEQV., generic intrinsic references, unrestricted character functions/substrings/concatenation, partial CHARACTER association, D/G/T/TL/TR editing, S/SP/SS, colon, Iw.m, Ew.dEe, and formatted direct access. See Appendix D for fine print.

- **DATA/COMMON nuance checked against standard §9.2:** Initializing named COMMON storage through DATA is permitted only in a BLOCK DATA subprogram, and BLOCK DATA is not F77S. Therefore the target is allowing legal local DATA even in program units that mention COMMON, **not** adding BLOCK DATA or allowing illegal initialization of COMMON objects.
